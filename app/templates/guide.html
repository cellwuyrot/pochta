Полный гайд по настройке SMTP-сервиса

Веб-порт — 3005; панель Docker доступна на localhost за HTTPS reverse proxy. SMTP AUTH требует STARTTLS и разрешённых доменов аккаунта. Входящие выключены по умолчанию. Для очереди используйте /api/outbox; SMTP acceptance не означает доставку в ящик. Полные инструкции обновления: UPGRADE.md в архиве.

1 Установка на VPS

Клонируйте репозиторий и запустите установку:

unzip smtp-updated-3005.zip
cd smtp-init-branch
bash setup.sh

Скрипт запросит:

  • Логин — имя пользователя для входа в админку
  • Пароль — пароль для админки (скрытый ввод)
  • Домен/IP — домен или IP вашего сервера (например {{ server_ip }})

После установки сохраните API-ключ из защищённого файла .env — он нужен для отправки писем через API.

2 Добавление сайта в админке

  1. Откройте Сайты → Добавить сайт
  2. Заполните:
    НазваниеМой сайт
    Доменexample.com
    Email отправителяnoreply@example.com
  3. SMTP-провайдер (необходим по умолчанию) — настройте внешний relay:
    Yandexsmtp.yandex.ru:587
    Gmailsmtp.gmail.com:587
    Mail.rusmtp.mail.ru:587
    Используйте «пароль приложения», а не основной пароль
  4. Direct MX выключен по умолчанию. Включайте ALLOW_DIRECT_MX только осознанно; рекомендуем настроенный SMTP-провайдер.

3 Настройка DNS записей

Зайдите в DNS-панель вашего хостинга (Cloudflare, REG.RU, Timeweb и т.д.) и добавьте записи. Посмотреть нужные записи можно на странице Сайты → DNS для вашего домена.

Обязательные записи:

Запись Тип Имя Значение Зачем
SPF TXT @ (или домен) v=spf1 ip4:{{ server_ip }} ~all Разрешает серверу отправлять письма
DMARC TXT _dmarc v=DMARC1; p=quarantine; rua=mailto:dmarc@ваш-домен Политика обработки неавторизованных писем

Опционально (для приёма входящих писем):

Запись Тип Имя Значение Приоритет
MX MX @ (или домен) mail.ваш-домен.ru 10
A A mail {{ server_ip }} —

MX запись указывает на hostname (не IP). Создайте A-запись mail.ваш-домен.ru → IP сервера, затем укажите её в MX.

Проверка: После добавления записей зайдите в Сайты → DNS и нажмите «Проверить DNS» — система автоматически проверит корректность всех записей.

4 Интеграция с вашим проектом

Добавьте в .env вашего проекта (Next.js, Node.js и т.д.):

# .env вашего проекта
SMTP_SERVICE_URL=http://{{ server_ip }}:3005
SMTP_API_KEY=sm_ваш_ключ_домена

API-ключ берётся из Сайты → DNS (у каждого домена свой уникальный ключ).

5 Отправка писем через API

Метод 1: Прямая отправка (рекомендуется)

POST /api/emails — отправляет письмо напрямую, не требует создания шаблона. 

curl -X POST http://{{ server_ip }}:3005/api/emails \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "from_email": "noreply@ваш-домен.ru",
    "to": "user@example.com",
    "subject": "Код подтверждения",
    "html": "<p>Ваш код: <b>123456</b></p>"
  }'

Метод 2: Через шаблоны

POST /api/send — использует шаблон, созданный в админке. Создайте шаблон в Шаблоны с переменными {% raw %}{{code}}{% endraw %}, {% raw %}{{name}}{% endraw %}. 

curl -X POST http://{{ server_ip }}:3005/api/send \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "site_domain": "ваш-домен.ru",
    "template_slug": "verification-code",
    "to_email": "user@example.com",
    "variables": {"code": "123456", "name": "Иван"}
  }'

6 Примеры кода

Next.js / TypeScript

// lib/email.ts
export async function sendEmail(to: string, subject: string, html: string) {
  const res = await fetch(`${process.env.SMTP_SERVICE_URL}/api/emails`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${process.env.SMTP_API_KEY}`,
    },
    body: JSON.stringify({
      from_email: 'noreply@ваш-домен.ru',
      to,
      subject,
      html,
    }),
  });

  if (!res.ok) {
    const err = await res.json();
    throw new Error(err.detail || 'Failed to send email');
  }

  return res.json(); // { id: "uuid", message: "Email sent" }
}

// Отправка кода подтверждения
export async function sendVerificationCode(email: string, code: string) {
  return sendEmail(
    email,
    'Код подтверждения',
    `<div data-css="legacy-46">
      <h2>Код подтверждения</h2>
      <p data-css="legacy-47">${code}</p>
      <p data-css="legacy-48">Код действителен 10 минут.</p>
    </div>`
  );
}

7 Обновление сервиса 

# Сначала сделайте backup БД, .env и ключей (UPGRADE.md)
# Обновите исходники из проверенного архива, не перезаписывая .env/volume
docker compose up -d --build

Данные и настройки (.env, data/smtp.db) сохраняются между обновлениями.

Частые проблемы

Проблема Причина Решение
ERR_CONNECTION_REFUSED Контейнер не запущен cd ~/smtp && docker compose up -d --build
422: No SMTP relay Домен не добавлен Добавьте сайт в админке или настройте RELAY_HOST в .env
Письма в спаме Нет DNS записей Добавьте SPF и DMARC записи (см. шаг 3)
Письма не доходят Порт 25 заблокирован VPS-провайдером Используйте relay (Yandex/Gmail) вместо прямой отправки
401: Invalid API key Неверный ключ Проверьте API_KEY в .env на VPS
.env: Is a directory Файл .env — это папка rm -rf .env && bash setup.sh
